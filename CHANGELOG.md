# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [SemVer](https://semver.org/lang/ru/).

## [1.1.1]

### Удалено

- Вопрос «Просмотреть скрипт перед запуском?» перед каждым вложенным установщиком. На практике его всегда пропускали: три лишних нажатия за установку, а читать `remnanode.sh` на 4970 строк в пейджере посреди процесса всё равно никто не станет. Строка «Получено строк: N» осталась — она показывает, что скачался скрипт, а не страница с ошибкой. Кому нужно вычитать вложенные установщики, разумнее делать это заранее по ссылкам из констант `R_REMNANODE`, `R_SELFSTEAL`, `R_WTM`.

## [1.1.0]

### Добавлено

- **Шаг 8 — файрвол.** Ставит ufw и приводит правила к схеме: наружу 22 (порт берётся из `sshd -T`, а не из конфига), 80 и 443; порт API ноды — только на интерфейсе `tailscale0`; остальное входящее запрещено. Порт ноды читается из `/opt/remnanode/.env` (`NODE_PORT`, у старых установок `APP_PORT`), вопрос задаётся только если прочитать не удалось.
- Отдельные вопросы: открыть тейлнету весь интерфейс или только порт ноды, и разрешать ли входящий `41641/udp` (по умолчанию да — иначе при неудачной пробивке NAT трафик уходит через DERP-релеи).
- Защита от блокировки: правило для SSH добавляется до `ufw enable`, и если после добавления его нет в `ufw status`, файрвол не включается.
- Проверка результата: политика по умолчанию, отсутствие глобального разрешения на порт ноды, список контейнеров с опубликованными наружу портами — Docker пишет правила в `DOCKER-USER` мимо ufw, и такие порты остаются открытыми даже при `deny incoming`.

### Изменено

- **BBR + fq вынесен из шага 1 в отдельный шаг 9, последний.** Раньше вопрос про BBR задавался в середине установки пакетов, хотя к ним отношения не имеет и на порядок ничего не завязано. Теперь установка идёт без пауз, а тюнинг ядра остаётся на конец, когда всё остальное уже работает. Шаг помечается в состоянии ключом `bbr` и пропускается при повторном запуске, как остальные.

## [1.0.2]

### Добавлено

- Запуск одной командой через подстановку процесса: `bash <(curl -fsSL .../bootstrap.sh)`. Вариант для минимального образа доставляет `curl` тем же вызовом. Пайп `curl | bash` по-прежнему непригоден и теперь объяснён в README: bash читает со stdin текст самого скрипта, вложенным установщикам канала для диалога не остаётся.

### Изменено

- Сообщение при запуске не от root больше не советует `sudo`: на минимальных образах его нет, а при запуске через `bash <(...)` в `$0` лежит `/dev/fd/63`, и совет получался бессмысленным.

## [1.0.1]

Исправления по итогам ревью. Две первые правки блокирующие: до них скрипт не запускался ни на одной поддерживаемой системе.

### Исправлено

- **Скрипт падал в preflight на любой Debian/Ubuntu.** Константа `readonly VERSION` конфликтовала с ключом `VERSION` из `/etc/os-release`: присваивание readonly-переменной в сорсимом файле — фатальная ошибка неинтерактивного bash, выполнение обрывалось с кодом 1 до первого шага, ERR-trap при этом не срабатывал. Константа переименована в `BOOTSTRAP_VERSION`, `/etc/os-release` теперь читается в субшелле.
- **Пароль можно было отключить при пустом `authorized_keys`.** `grep -c` печатает `0` и одновременно возвращает 1, поэтому `$(grep -c ... || echo 0)` давал строку `"0\n0"`, `(( nkeys == 0 ))` становился синтаксической ошибкой арифметики и вычислялся как false — защита «ключей нет, харденинг пропускаем» не срабатывала. Подсчёт вынесен в `count_keys()` на базе `ssh-keygen -l`, перед арифметикой значение проверяется регуляркой.
- **Ключи с опциями и FIDO-ключи не считались.** Прежний `grep -E '^(ssh|ecdsa)-'` не видел ни `sk-ssh-ed25519@openssh.com`, ни строк вида `restrict,command="..." ssh-ed25519 ...`. `ssh-keygen -l` понимает оба формата.
- **Ложный диагноз «Нет доступа к github.com» на минимальном образе.** `curl` использовался в preflight и в `public_ip` до того, как шаг 1 его установит; при отсутствии бинарника получался exit 127 и сообщение о недоступной сети на исправно работающей машине. Теперь `curl` доставляется в preflight до сетевых проверок.
- **Сбой установки acme.sh обрывал весь запуск.** `prepare_acme` вызывал `die`, хотя `step_selfsteal` написан как `prepare_acme || { warn; return 0; }` и рассчитан пропустить шаг и идти дальше. Заменено на `err` + `return 1`.
- **Запуск без sudo печатал ложное «Прервано на строке».** `log()` писал в `/var/log` через `tee`; без прав `tee` падал, `pipefail` делал возврат `err()` ненулевым, срабатывал ERR-trap и затирал единственное полезное сообщение — «Нужен root». Теперь запись идёт напрямую и не влияет на код возврата.
- **На чистом сервере предлагалось не добавлять ключ.** Подсчёт уже имеющихся ключей страдал от той же ошибки с `grep -c`, из-за чего `addkey_default` оставался `n` — то есть по умолчанию предлагался ответ «нет» ровно в ситуации, где ключ обязателен, — и пользователь видел в консоли ошибку арифметики bash.

## [1.0.0]

Первый выпуск.

### Добавлено

- Семь шагов установки: базовые пакеты и BBR, вход по SSH-ключу, Tailscale, проверка A-записи, `remnanode.sh`, `selfsteal.sh` с подготовкой acme.sh, WARP по варианту B.
- Состояние в `/var/lib/remnanode-bootstrap/state` — пройденные шаги пропускаются при перезапуске.
- Обход конфликта SSH-дропинов хостера: директивы пишутся в основной `sshd_config` перед строкой `Include`.
- Поддержка socket-активации sshd в Debian 13 и Ubuntu 24 (`restart ssh.socket` вместо `reload ssh`).
- Обход падения регистрации аккаунта acme.sh из-за невалидного автогенерируемого e-mail.
- Бэкапы изменяемых конфигов в `/root/remnanode-bootstrap-backups/`, лог в `/var/log/remnanode-bootstrap.log`.
